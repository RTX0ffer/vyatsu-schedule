# 🚀 Telegram Schedule Bot на x86_64 Assembler (FASM) для Linux

Полнофункциональная реализация Telegram-бота расписания ВятГУ, написанная на **чистом ассемблере x86_64** с использованием синтаксиса **Flat Assembler (FASM)** под ОС Linux (ELF64).

---

## ⚡ Особенности реализации

- **Чистый x86_64 Assembly**: код написан на ассемблере FASM в формате `ELF64` в соответствии с системным соглашением о вызовах **System V AMD64 ABI**.
- **Минимальное потребление ресурсов**: бинарный файл занимает считанные килобайты, а потребление оперативной памяти в рантайме составляет **менее 2 МБ** (в сравнении с 60–120 МБ у Python-версии).
- **Мгновенный отклик**: обработка входящих запросов и форматирование сообщений происходят за доли микросекунд (`< 0.5 ms`).
- **Полноценный сетевой стек (HTTPS / TLS 1.3)**: взаимодействие с Telegram Bot API осуществляется через `libcurl`, что гарантирует надёжное шифрование, валидацию сертификатов и поддержку long-polling.
- **Встроенный JSON-парсер и экранировщик**: легковесный лексер JSON без внешних тяжелых зависимостей.
- **Интерактивная клавиатура Telegram**: поддержка нативных кнопок меню (`ReplyKeyboardMarkup`), идентичных Python-боту.
- **Динамический расчёт дат**: использование системных вызовов времени POSIX (`time`, `localtime`) для точного определения текущего дня, завтрашнего дня и дней недели с учётом выходных.

## 📁 Структура проекта `fasm_bot/`

| Файл | Описание |
|---|---|
| `bot.asm` | Главный модуль: точка входа `main`, long-polling цикл (`getUpdates`), парсинг обновлений, диспетчер команд и отправка сообщений (`sendMessage`). |
| `http_client.inc` | Сетевой модуль: динамический буфер памяти, коллбэк для curl, функции `http_get` и `http_post_json`. |
| `json_helper.inc` | Ассемблерные утилиты JSON: поиск ключей, парсер 64-битных чисел, парсер строк с разэкранированием и экранировщик для JSON payload. |
| `schedule_data.inc` | Данные расписания по дням недели, шаблоны сообщений, ссылки на календари (.ics), названия дней на русском языке и разметка кнопок. |
| `Makefile` | Универсальный скрипт сборки для GNU Make (`make`, `make clean`, `make run`). |
| `build.sh` | Bash-скрипт сборки с автоматической проверкой установленных зависимостей. |
| `Dockerfile` | Контейнер Ubuntu 22.04 для сборки и запуска в Docker на любой платформе. |

## 🛠 Системные требования и установка зависимостей

Для сборки требуются:
- **ОС:** Linux x86_64 (любой дистрибутив)
- **FASM:** Flat Assembler (`fasm`)
- **GCC:** GNU Compiler Collection (для компоновки со стандартными библиотеками)
- **libcurl:** Библиотека libcurl с заголовочными файлами

### Ubuntu / Debian / Linux Mint:
```bash
sudo apt-get update
sudo apt-get install -y fasm gcc make libcurl4-openssl-dev
```

### Arch Linux / Manjaro:
```bash
sudo pacman -S fasm gcc make curl
```

### Fedora / RHEL / AlmaLinux:
```bash
sudo dnf install -y fasm gcc make libcurl-devel
```

## 🐳 Запуск через Docker

Если вы работаете на macOS или Windows, либо хотите запустить бота в изолированном контейнере:

```bash
cd fasm_bot

# Сборка образа
docker build -t vyatsu-fasm-bot .

# Запуск контейнера
docker run -d --name schedule-bot \
  -e BOT_TOKEN="ваш_токен_бота" \
  --restart unless-stopped \
  vyatsu-fasm-bot
```

Просмотр логов:
```bash
docker logs -f schedule-bot
```

## ⚙️ Запуск в качестве Systemd-сервиса (Автозапуск 24/7)

Создайте файл службы `/etc/systemd/system/fasm-bot.service`:
```ini
[Unit]
Description=VyATSU Schedule Telegram Bot (FASM x86_64 Linux)
After=network.target

[Service]
Type=simple
User=your_user
WorkingDirectory=/path/to/fasm_bot
Environment="BOT_TOKEN=ваш_токен_бота"
ExecStart=/path/to/fasm_bot/bot
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

Активация и запуск службы:
```bash
sudo systemctl daemon-reload
sudo systemctl enable --now fasm-bot
sudo systemctl status fasm-bot
```

## 🧠 Технические детали ассемблерного кода

1. **System V AMD64 ABI**:
   - Аргументы передаются в регистрах: `RDI`, `RSI`, `RDX`, `RCX`, `R8`, `R9`.
   - Для вариативных функций (`printf`, `snprintf`, `curl_easy_setopt`) регистр `RAX` обнуляется (`xor eax, eax`).
   - Сохраняемые регистры (`RBX`, `R12`–`R15`, `RBP`, `RSP`) строго сохраняются в прологах функций.
   - Стек перед всеми инструкциями `call` выровнен по границе **16 байт** (`RSP % 16 == 0`), что исключает аппаратные исключения `SIGSEGV` в векторных SSE/AVX-инструкциях glibc.

2. **Экранирование JSON**:
   Функция `json_escape_string` за один проход на регистрах преобразует спецсимволы (`"`, `\`, `\n`, `\r`, `\t`) в валидный JSON-формат, корректно пропуская многобайтовые UTF-8 последовательности (русские символы и эмодзи).

3. **Управление памятью**:
   Сетевой буфер `MemoryBuffer` динамически масштабируется через `realloc`, удваивая ёмкость по мере поступления пакетов от Telegram Bot API, предотвращая переполнение буфера.
